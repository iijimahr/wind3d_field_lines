# 要件

## 言語

コード・コメント・ドキュメントはすべて英語で記述すること。
ただし、AGENTS.mdなどエージェント用のファイルは日本語で良い。

## ディレクトリ構成

- 一般的なPythonプロジェクトの構成を採用すること。
  - 例: <https://github.com/iijimahr/goes_xrs_synthesis>
- `pyproject.toml`をプロジェクトのルートに配置すること。
- `src/`: ソース
- `tests/`: テスト
- `docs/`: ドキュメント
- `.github/`: GitHub Actionsのワークフロー等

## `pyproject.toml`の内容

- ミニマムを心がけること。
- `pytest, ruff, mypy`などは利用して良い。mypyは重いので必須にはしない。
- 開発用の依存関係を明確にすること。

## テスト

- `pytest`を利用した単体テストを実装すること。

## ドキュメント

- `sphinx`を利用して、コードのドキュメントを生成すること。
- ドキュメントは英語で記述すること。

## CI/CD

- GitHub Actionsで自動化すること。
- テストの実行、コードのスタイルチェック、型チェックなどを含めること。
- マージ時にはドキュメントのビルド・デプロイを行うこと(push時にはデプロイはしない)。

## 直交座標系への対応

- デカルト座標系での磁場線の追跡問題と、任意の直交曲線座標系での磁場線の追跡問題が同一であることをドキュメントに明示すること。
  - その論理は`orthogonal_coordinates.md`に記述してある。
- 直交曲線座標系における磁力線追跡を実施する関数を実装すること。
  - 直交曲線座標系における物理量が以下のように関数の引数として与えられる:
    - `dxi`: \(\Delta_\xi\) - \(\xi\)方向の計算格子幅 (スカラー)
    - `det`: \(\Delta_\eta\) - \(\eta\)方向の計算格子幅 (スカラー)
    - `dzt`: \(\Delta_\zeta\) - \(\zeta\)方向の計算格子幅 (スカラー)
    - `hxi`: \(h_\xi\) - \(\xi\)方向のスケールファクター (\(\zeta\)にのみ依存する1次元配列)
    - `het`: \(h_\eta\) - \(\eta\)方向のスケールファクター (\(\zeta\)にのみ依存する1次元配列)
    - `hzt`: \(h_\zeta\) - \(\zeta\)方向のスケールファクター (\(\zeta\)にのみ依存する1次元配列)
    - `bxi`: \(B_\xi\) - \(\xi\)方向の磁場の物理成分
    - `bet`: \(B_\eta\) - \(\eta\)方向の磁場の物理成分
    - `bzt`: \(B_\zeta\) - \(\zeta\)方向の磁場の物理成分
  - 実装は以下のように与えること:
    - (1) 磁場を適切にスケールする。
    - (2) デカルト座標系で磁力線追跡関数を呼び出し磁力線を追跡する。
    - (3) 追跡された磁力線を元の直交曲線座標系に変換して返す。

## デモ

- `src`ディレクトリ内に、コードの使用例を示すデモスクリプトを配置すること。
- デモは、コードの主要な機能を示すものであること。
- 磁場データには`arcade_field_demo.md`の線形フォースフリー磁場を利用すること。
  - ドキュメントには、この磁場の数式と特徴を説明すること。
  - ドキュメントには、可視化結果(svgまたはpngファイル)を掲載すること。
- デモの出力は、`matplotlib`を利用した磁力線の3D可視化とすること。
  - `pyvista`などの高度な可視化ライブラリは利用しないこと。
- `docs/`にはこのデモ問題の解説も掲載すること。
- デモはコマンド形式ではなく、例としてドキュメント内で紹介する形にすること。
  - ただし、磁場データの作成関数はコマンド形式で提供すること。

## ポテンシャル磁場モデル

- ポテンシャル磁場モデルを実装すること。
- これは、磁場線の追跡関数とは独立した関数として実装すること。
- 詳細は`potential_field_extrapolation.md`に記述してある。

## レガシーコードとリファクタリング

- `legacy/`ディレクトリに既存のFortranコードを配置する。
  - 無印と`*v2*`があるが、基本は`*v2`を利用する。
  - ファイル名や関数名は引き継がず、適切な命名を再検討すること。
- 既存のFortran+f2pyによるコードが存在する。
- これを再配布可能な形にリファクタリングする。
- 動作速度に懸念があれば、nanobindを利用するが、まずはf2pyで実装すること。
- f2pyは特にコンパイルの環境依存が強いので、再配布に強い形を心がけること。
